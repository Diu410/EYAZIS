# Лабораторная работа 3: реферирование документов

Два метода для русского и немецкого текста:

- **Генеративный**: локальная Qwen 3.5 4B через Ollama создаёт связный реферат с новыми формулировками. Этот метод выбран по умолчанию в веб-интерфейсе.
- **Экстрактивный**: TF·IDF и позиционные коэффициенты выбирают наиболее информативные предложения исходника и восстанавливают их порядок.

В обоих режимах показываются ключевые слова **исходного документа** с весами TF·IDF. Веса исходных предложений служат анализом текста; в генеративном режиме они не определяют выбор фраз модели. Результаты, включая исходник и сведения о методе, хранятся в SQLite.

## Запуск

Нужен Python 3.10 или новее. Дополнительные Python-пакеты не требуются. Для генерации нужен работающий локальный Ollama с установленной моделью:

```powershell
ollama list
python app.py
```

В списке должна быть `qwen3.5:4b`. Если Ollama не запущен, откройте приложение Ollama либо выполните `ollama serve` в отдельном терминале. Существующая модель используется без повторного скачивания.

1. Откройте <http://127.0.0.1:8765/summary>.
2. Выберите текст из тестовой коллекции, вставьте свой текст либо загрузите TXT/MD. Можно перейти со страницы документа лабораторной 1 или 2.
3. Выберите метод, язык, предметную область и максимальное количество предложений. Нажмите «Построить реферат».
4. Дождитесь ответа Qwen; первый вызов включает загрузку модели. Результат показывает модель, время, реферат и ключевые слова. Для длинных текстов отображается число обработанных фрагментов.
5. Скачайте TXT/JSON или распечатайте результат. Ссылка «Открыть исходный документ» открывает сохранённый исходник, включая ручной ввод. История показывает метод каждого результата.

Если модель недоступна, появляется понятная ошибка, введённый текст остаётся в форме и результат не сохраняется. Старые экстрактивные рефераты продолжают открываться; схема SQLite автоматически обновляется при запуске.

## Генеративный алгоритм

`lab3/generative.py` обращается к [Ollama /api/chat](https://github.com/ollama/ollama/blob/main/docs/api.md) через стандартный `urllib.request`. Запрос содержит полный текст, язык, предметную область и ограничение числа предложений. Из JSON-ответа API берётся только конечный текст `message.content`; программа проверяет завершённость и число предложений реферата. Сам реферат генерируется обычным текстом, чтобы кавычки в названиях произведений не обрывали JSON-строку. Обрыв ответа по лимиту токенов считается ошибкой. Если модель превышает число предложений, выполняется один дополнительный запрос на сжатие; конец текста не обрезается.

Используется `think=false`, температура 0 и seed 42; штраф повторов сброшен, чтобы не мешать повторению терминов и чисел. Результат содержит имя модели, число запросов, входных и выходных токенов, время и стратегию обработки. Повторяемость зависит также от версии модели и Ollama.

Документы длиннее 6000 символов делятся с предпочтением границ абзацев и предложений. Каждый фрагмент сжимается моделью, промежуточные результаты объединяются и сжимаются до общего реферата. Все части исходника участвуют в обработке. Предел входа — 120 000 символов, контекст одного запроса — 16 384 токена, максимум итоговых предложений — 30. Ключевые слова вычисляются по полному исходнику.

Настройки через переменные окружения PowerShell:

```powershell
$env:OLLAMA_BASE_URL = "http://127.0.0.1:11434"
$env:OLLAMA_MODEL = "qwen3.5:4b"
$env:OLLAMA_TIMEOUT = "300"  # секунды на один запрос
python app.py
```

Программный вызов:

```python
from lab3 import summarize

result = summarize(
    "Алгоритм обрабатывает данные. Проверка подтвердила правильность результата.",
    language="ru", method="generative", max_sentences=2,
    subject_area="computer science",
)
print(" ".join(result["summary"]))
print(result["keywords"])
print(result["model"], result["generation"]["elapsed_ms"])
```

Также доступна функция `lab3.summarize_generative(...)`. Для совместимости вызов `summarize(...)` без `method` использует экстрактивный метод.

## Экстрактивный алгоритм

`lab3/summarizer.py`: вес слова `0.5 × (1 + TF(t,D)/TFmax(D)) × ln(N/DF(t))`; лексический вес предложения `Σ TF(t,Si) × w(t,D)`; итог умножается на `(1 − BD(Si)/|D|) × (1 − BP(Si)/|P|)`.

IDF считается по полным документам языка из `corpus/` или явно переданного `reference_documents`. Вход добавляется один раз, дубликаты исключаются. Абзацы и предложения не являются единицами IDF. Для встроенного образца N=2; для нового текста обычно N=3. Результат содержит `idf_document_count`, `idf_unit`, `algorithm_version` и `method`.

Сегментация учитывает десятичные числа, инициалы, распространённые русские и немецкие сокращения и закрывающие кавычки. Незавершённый хвост не выбирается. Из русских ключевых слов исключаются числа, латинские слова и стоп-слова; из немецких — стоп-слова. Для классического реферата рекомендовано около десяти предложений; короткий исходник почти не сокращается.

## Коллекция и проверка

В `lab3/corpus/` находятся четыре учебных авторских документа по 4500 символов: научные статьи об алгоритмах поиска и литературные сочинения о «Преступлении и наказании», на русском и немецком. Материалы подготовлены с помощью ИИ. Исходные абзацы — `documents.json`, метаданные — `sources.json`. `python -m lab3.prepare_corpus` воспроизводит коллекцию офлайн. Длина выравнивается целыми предложениями.

```powershell
python -m unittest lab3.test_regressions -v
python -m unittest lab3.test_generative -v
python -m lab3.benchmark --method both --repeats 1
```

Проверки без модели охватывают протокол, недоступный сервер, некорректный/оборванный ответ, длинные тексты, обновление старой БД, сохранение формы при ошибке и экспорт через HTTP. Последняя команда выполняет **реальные вызовы локальной Qwen** для всех четырёх документов и сравнивает методы.

Для экстрактивного метода сохраняются точность, полнота и F1 совпадений предложений с фиксированным учебным эталоном `reference_annotations.json`. Для обоих методов считаются ROUGE-1 и ROUGE-L: совпадения слов и чисел без учёта регистра, без стемминга. Это лексическое сходство; оно не измеряет достоверность фактов. Точные совпадения предложений не используются для генеративного метода, поскольку модель переформулирует текст. Численные факты и выводы реферата следует сопоставлять с исходником.

Замер генерации включает загрузку модели, если она ещё не загружена. По умолчанию выполняется 10 повторов для экстрактивного метода и один для генеративного; можно задать `--repeats`. При одном повторе стандартное отклонение не вычисляется. Учебная разметка подготовлена с помощью ИИ и не заменяет независимую экспертную оценку.
